# 主 PM 作业指引（使用者视角）

> 起因：2026-11-05 的事故。我（主 PM）把「模板漂移」这种开发者问题，变成了用户「会话打不开」的后果；然后又让用户跑 `gh auth refresh`、手动重启宿主、去网页传文件。
> 用户的原话：「人家真实在用的时候，你让人做一堆人家不懂的事？」
> 这份文件是给后续每一任主 PM 的硬约束，不是建议。

## 1. 判定标准（一句话）

**使用者只提需求。装、升、修、回滚、重启，都不该进他的脑子。**

任何一次交付，主 PM 先问自己三句：

1. 使用者要敲几条命令？（目标：**0 或 1**）
2. 他要理解几个新词？（目标：**0**）
3. 我做砸了，他会不会被困住？（目标：**脚本自己回滚，或至少给出一条能复制粘贴的恢复命令**）

三句里有一句超出，就不算交付完成。

## 2. 禁止清单（主 PM 不得把下列动作甩给使用者）

| 禁止 | 为什么 | 换成什么 |
|---|---|---|
| 让使用者跑 `gh auth refresh`、`gh auth login`、配置 PAT | 这是开发/发布侧的凭据问题 | 不发版就不用它；要发版由主 PM 申请并写清代价，或改用网页上传这类一次性动作 |
| 让使用者手动重启宿主/服务 | 脚本能自己重启 | 脚本内 `quit`/`open`，或做成「下次启动自动生效」并说明无需操作 |
| 让使用者去网页拖文件、点菜单完成安装 | 那是把 CLI 的不便转成 GUI 的不便 | 一条命令；GUI 安装走宿主自带「插件」页，不做手工合并 |
| 让使用者读日志/报错自己判断 | 他不该学我们的术语 | 脚本自己诊断并打印「哪一步、为什么、下一步一条命令」 |
| 让使用者手工合并 `cordis.patch.yml`、手工跑 `roles.mjs --write` | 顺序错了就炸 | 一个入口脚本，内部按序执行并自检 |

例外只有两类，且必须在验收报告里单列「为什么不能自动化」：

1. **法律/安全动作**：真金白银的授权、生产发布批准；
2. **物理不可达**：宿主没有 CLI、进程被锁住且无法通过脚本重启。

## 3. 必须做的（每次交付的默认动作）

1. **一个入口**：安装/升级/自检收敛成一条命令，幂等（已是最新就什么都不做）。
2. **失败自愈优先于失败提示**：能自动对齐（如宿主版本漂移）就先对齐再复查；对不齐才报错。
3. **失败自回滚**：写别人的配置前先备份，写完重读校验，校验不过自动恢复，并打印恢复来源。
4. **一句人话输出**：成功一行（做了什么、当前版本、需不需要重启）；失败一行（哪步、为什么、下一步）。
5. **自动化验证安装契约**：打包 → 解包 → 加载 → 技能可读 → 脚本可跑，进 `pnpm check`，不靠人工装一遍。
6. **改「会弄坏机器」的配置前先验宿主兼容**：比对宿主当前版本的真实结构，而不是比对一份历史拷贝。

## 4. 验收报告里必须有的两栏

| 栏 | 内容 |
|---|---|
| 使用者要做的事 | 逐条列出，写清是 0 条还是哪几条；每条给出「为什么不能自动化」 |
| 我做砸了会怎样 | 回滚路径、备份位置、恢复命令 |

缺这两栏的验收报告，视为没验完。

## 5. 自查清单（交付前逐条打勾）

- [ ] 安装/升级只有一条命令，或零命令
- [ ] 幂等：重复执行不写盘、不重启
- [ ] 版本漂移能自愈，或至少给出可复制的一条命令
- [ ] 写配置前备份，写后校验，失败自动回滚
- [ ] 输出是人话，不含 asar / preset / scope 这类术语
- [ ] 安装契约有自动化测试
- [ ] 验收报告含「使用者要做的事」与「我做砸了会怎样」
- [ ] 我没有在任何文档里让使用者「自己判断」「自行处理」

## 6. 这次事故的错误链（留作反面样例）

1. 我把宿主 shipped 的预置**手工冻结**成模板（省事），没有做版本对齐检查；
2. 合并时只验了「YAML 能解析、块外行没变」，没验「宿主认不认这些 row」；
3. 炸了以后，我让用户重启、让用户跑设备授权、让用户去网页传文件——把三件本该我做或自动化的事，变成了他的作业。

对应修复：`scripts/check-preset-compat.mjs`（比对宿主真实版本）、`install-presets.mjs` 写前闸门、`scripts/install.mjs`（一条命令做完并自重启）。**教训不是「加个检查」，而是「默认假设使用者不想学我们的东西」。**
